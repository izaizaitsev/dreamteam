# AI Legal Copilot: входящие обращения

Локальный MVP по приложенной спецификации: импорт JSON из Bitrix24 через адаптер, очередь и карточка обращения, поиск решённых кейсов в Qdrant, локальные embedding и reranker, классификация и проект ответа через GigaChat, проверка и правка человеком, аудит, шаблоны и явное добавление решённого обращения в индекс.

## Требования

- Python 3.12+ и [uv](https://docs.astral.sh/uv/);
- Docker Compose и GPU для контейнера reranker из текущего `compose.yaml`;
- ключ авторизации GigaChat (Authorization key).

Приложение запускается на хосте, а локальные модели и Qdrant — в Docker. Порты и имена моделей берутся из **существующего** `.env` и `compose.yaml`. База MVP — локальный SQLite-файл `app/data/appeals.sqlite3`; `.env` и база исключены из Git.

## Настройка и запуск (PowerShell, из корня проекта)

Если `.env` уже есть, сохраните его. Для новой установки скопируйте `.env.example` в `.env` и при необходимости поменяйте параметры Docker. В `.env` добавьте:

```env
GIGACHAT_AUTH_KEY=ВАШ_AUTHORIZATION_KEY
```

Это значение — ключ из личного кабинета GigaChat, который передаётся в заголовке `Authorization: Basic`. Не вставляйте сюда OAuth access token. По желанию задайте `APP_API_KEY` для защиты локального API; интерфейс запросит его при первом запросе.

```powershell
docker compose up -d
uv sync --project app
uv run --project app uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте <http://127.0.0.1:8000/>. Документация API: <http://127.0.0.1:8000/docs>.

## Как проверить

```powershell
uv run --project app python -m unittest discover -s app/tests -v
```

Тесты подменяют внешние AI-сервисы и проверяют сквозной путь от импорта до одобрения и сохранения решённого кейса. Для живой проверки:

1. Убедитесь, что `/health/db`, `/health/embedding`, `/health/reranker`, `/health/gigachat` доступны. Последний проверяет только наличие ключа и не тратит OAuth-токен.
2. На вкладке **Импорт** загрузите `examples/resolved-cases.json`, включите «Сразу индексировать», затем загрузите `examples/appeals.json`.
3. Откройте обращение `DEMO-001`, нажмите **Запустить AI-анализ**. Проверьте похожие кейсы, классификацию, источники контекста, предупреждения и черновик.
4. Отредактируйте текст, укажите имя проверяющего, нажмите **Одобрить**. Только после одобрения нажмите **Отметить решённым**, при желании включите индексацию.

Повторная загрузка того же `external_id` не создаёт дубль. Ошибочные строки отражаются в отчёте импорта, остальные сохраняются. Повторный AI-анализ создаёт новые записи результатов и черновиков; исходный AI-текст сохраняется отдельно от правок.

## Формат данных и ограничения пилота

Импорт принимает массив JSON или объект с полем `items`, `appeals`, `cases` либо `result`. Для обращений нужны `external_id` и `text`; также распознаются типичные поля `ID`, `TITLE`, `DESCRIPTION`, `STATUS_ID`. Реальная схема выгрузки Bitrix24 ещё не предоставлена: её сопоставление сосредоточено в `app/importers.py`.

Для решённых кейсов нужны `external_id` и `appeal_text`; `decision_text` и `decision_file_uri` необязательны. Внутренние системы пока не подключены: контекст читается только из `context` в импортированном JSON, отсутствие данных явно показывается в карточке и передаётся в предупреждения черновика. Шаблоны создаются на вкладке **Шаблоны**. Итоговый ответ заявителю приложение автоматически не отправляет.

В этом локальном MVP нет учётных записей и ролей: `APP_API_KEY` — один общий ключ. До использования с реальными персональными данными нужны авторизация по пользователям, роли, HTTPS, решение о передаче персональных данных в GigaChat и подключение реальных внутренних источников. Флаг `LLM_MASK_PII=true` маскирует телефон и email, но не все виды персональных данных.
