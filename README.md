# AI-юрист по вопросам ЖКХ

Локальный MVP по приложенной спецификации: импорт JSON из Bitrix24 через адаптер, очередь и карточка обращения, поиск решённых кейсов в Qdrant, локальные embedding и reranker, классификация и проект ответа через GigaChat, проверка и правка человеком, экспорт одобренного ответа в Word, аудит, шаблоны и явное добавление решённого обращения в индекс.

## Запуск одной командой

Нужны Docker Compose и NVIDIA GPU для локального reranker из `compose.yaml`. Из корня проекта выполните:

```powershell
docker compose up -d --build
```

Откройте <http://127.0.0.1:8000/>. Все действия выполняются в веб-интерфейсе: **Настройки**, **Импорт**, **Обращения**, **Шаблоны**, **Индекс**, **Журнал**. При первом запуске модели могут загружаться несколько минут; их состояние видно в **Настройках**.

В **Настройки → Ключ GigaChat** вставьте *Authorization key* из кабинета GigaChat и нажмите **Сохранить ключ**. OAuth access token сюда не подходит. Ключ хранится в постоянном томе приложения, не возвращается API и не попадает в образ Docker. Уже существующий `.env` продолжает задавать параметры локальных моделей из `compose.yaml`; запуск работает и без `.env` за счёт значений по умолчанию.

База, Word-файлы и ключ GigaChat хранятся в томе `practicum3-app-data`. Для совместной работы можно задать отдельные `ADMIN_API_KEY`, `LAWYER_API_KEY`, `OPERATOR_API_KEY` в `.env` и перезапустить контейнеры той же командой. Тогда интерфейс запросит ключ доступа. По умолчанию порты доступны только с `127.0.0.1`.

## Полный путь по интерфейсу

1. Откройте <http://127.0.0.1:8000/> → **Настройки**. Дождитесь `ok` у базы, embedding и reranker. В поле **Ключ GigaChat** вставьте Authorization key → **Сохранить ключ**.
2. Нажмите **Импорт** → блок **1. Решённые обращения** → **Выбрать файл** → выберите `examples/resolved-cases.json` → оставьте отметку **Сразу индексировать** → **Загрузить решённые**. В отчёте проверьте `created` и `indexed`.
3. Если у решённого обращения есть заполненный Word-файл, оставайтесь на **Импорт** → блок **3. Word-файл решения** → введите его `external_id` из JSON → **Выбрать файл** `.docx` → **Прикрепить Word**. Система сохранит файл и извлечёт из него полный текст ответа. Этот шаг можно пропустить, если полный ответ уже указан в `decision_text` JSON.
4. На той же странице откройте блок **2. Новые обращения** → **Выбрать файл** → выберите [`examples/new-appeals.json`](examples/new-appeals.json) → **Загрузить новые**. При первом импорте отчёт покажет `created: 2`, при повторном — `skipped: 2`.
5. Нажмите **Обращения** → строку `DEMO-NEW-001` → **Запустить AI-анализ**. Смотрите блоки **AI-анализ**, **Контекст**, **Похожие обращения** и **Черновик и проверка**. Если у похожего кейса загружен Word, в блоке **Word-файлы решений** нажмите **Скачать …**.
6. В блоке **Черновик и проверка** измените текст → укажите имя проверяющего → **Сохранить** → **Одобрить**. Затем нажмите **Скачать Word**. При необходимости оставьте отмеченным **Сразу индексировать** → **Отметить решённым**.

Образцы JSON также скачиваются по ссылкам прямо на странице **Импорт**. Если модель определит, что юрист не требуется, черновик ответа автоматически не создаётся.

## Где хранится само решение

| Что | Где |
| --- | --- |
| Полный ответ ранее решённого обращения из JSON | `decision_text` таблицы `cases` в SQLite `/data/appeals.sqlite3` контейнера `app` |
| Прикреплённый Word-файл ранее решённого обращения | `/data/documents/resolved/<case_id>.docx` в контейнере `app`; путь записан в `decision_file_uri` |
| Одобренный ответ на новое обращение | `edited_text` таблицы `drafts`; после **Скачать Word** файл `/data/documents/<draft_id>.docx` |

Эти файлы и база находятся в постоянном Docker-томе `practicum3-app-data`. Qdrant хранит векторы для поиска, а не текст решения. После скачивания Word копия также появляется в папке загрузок вашего браузера.

При JSON-импорте поле `decision_file_uri` — только ссылка/путь к внешнему файлу; сам файл копируется в том приложения именно кнопкой **Прикрепить Word**.

## Автоматическая проверка

Автоматические тесты разработчика при установленном Python и uv:

```powershell
uv run --project app python -m unittest discover -s app/tests -v
```

Повторная загрузка того же `external_id` не создаёт дубль. Ошибочные строки отражаются в отчёте импорта, остальные сохраняются. Повторный AI-анализ создаёт новые записи результатов и черновиков; исходный AI-текст сохраняется отдельно от правок.

## Формат данных и ограничения пилота

Импорт принимает массив JSON или объект с полем `items`, `appeals`, `cases` либо `result`. Для обращений нужны `external_id` и `text`; также распознаются типичные поля `ID`, `TITLE`, `DESCRIPTION`, `STATUS_ID`. Реальная схема выгрузки Bitrix24 ещё не предоставлена: её сопоставление сосредоточено в `app/importers.py`.

Для решённых кейсов нужны `external_id` и `appeal_text`; полный утверждённый ответ следует указать в `decision_text` или прикрепить позже как `.docx`. `decision_file_uri` можно передать в JSON как ссылку на внешний документ, но это не загрузка файла. Внутренние системы пока не подключены: контекст читается только из `context` в импортированном JSON, отсутствие данных явно показывается в карточке и передаётся в предупреждения черновика. Шаблоны создаются на вкладке **Шаблоны**. Итоговый ответ заявителю приложение автоматически не отправляет.

Роли `ADMIN`, `LAWYER`, `OPERATOR` разделяются отдельными API-ключами; это упрощённая авторизация пилота, без учётных записей и индивидуальной идентификации сотрудников. До использования с реальными персональными данными нужны полноценная авторизация пользователей, HTTPS, решение о передаче персональных данных в GigaChat и подключение реальных внутренних источников. Флаг `LLM_MASK_PII=true` маскирует телефон и email, но не все виды персональных данных.
